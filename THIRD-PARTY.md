# Third-Party Notices

This site serves two files that are not original work: `assets/cangjie-data.js`,
the Cangjie dictionary the in-page typing demo runs on, and
`assets/vendor/three.module.min.js`, the graphics library the landing page's
interactive water scene renders with. Everything else in this repository —
the renderer, the stylesheet, the demo logic in `assets/keyboard-demo.js`, and
all page content — is original.

## Cangjie dictionary — `assets/cangjie-data.js`

`assets/cangjie-data.js` is generated by `scripts/build_cangjie_data.py` from
`cangjie35_mobile.cin`, the mobile-tuned build of the merged Cangjie 3 + 5 table
in the KOI application repository, reduced to the characters that appear in
Conway's traditional-character commonality ranking. (`cangjie35_mobile.cin` is
an intermediate of that derivation; the shipping application bundles
`cangjie35_personal.cin` from the same lineage.) It is a derived work of:

### Why the rest of the site is not LGPL

`assets/cangjie-data.js` is a standalone ES module. `assets/keyboard-demo.js`
imports two named exports from it and uses nothing else. The file can be
replaced with a differently-licensed dictionary of the same shape — two exports,
`RADICALS` and `TABLE` — without modifying any other file in this repository.

That separability is the condition LGPL-3.0 §4 sets for combining an LGPL'd
component with a work under other terms, so the remainder of this repository
stays under its own licence.

### Modifications made

The generator is committed at `scripts/build_cangjie_data.py` and its output is
committed rather than built at deploy time, so every change to the dictionary
appears as a reviewable diff. The transformations applied are:

- merging the Cangjie 3 and Cangjie 5 code sets into one table;
- restricting characters to the Basic Multilingual Plane;
- re-weighting candidate order by character frequency, including a Hong Kong
  Cantonese usage boost;
- dropping characters absent from Conway's ranking, and truncating each code to
  at most 12 candidates.

To regenerate:

```
python3 scripts/build_cangjie_data.py \
    --cin  ../urkeyboard/cangjie35_mobile.cin \
    --rank ../urkeyboard/ranking-traditional.txt
```

## Three.js — `assets/vendor/`

Three.js is the WebGL library the landing page's interactive water scene is
built with. It is vendored into this repository rather than loaded from a CDN,
so the site keeps its promise of loading nothing from any other host. Both files
are unmodified from upstream:

- `assets/vendor/three.module.min.js`
- `assets/vendor/three.core.min.js`

Upstream splits the build in two and the module half imports the core half by
relative path, so both must be present; shipping only the first produces a
"failed to fetch dynamically imported module" error at runtime.

| Upstream | Licence | Source |
| --- | --- | --- |
| Three.js | MIT | <https://github.com/mrdoob/three.js> |

### Licence

Both vendored files are distributed under the **MIT licence**, unchanged from
upstream. The licence text is in `licenses/three-MIT.txt`.

The library is loaded only by the landing page, and only after the page has
established that a scene is both wanted and possible: a visitor who asked for
reduced motion, or whose browser has no WebGL, never downloads it.

## Not used

This site loads no web fonts, no analytics, no tag manager, no CDN asset, and no
third-party frame, script, or stylesheet. `scripts/verify_site.py` enforces that
on every deploy: it rejects any `<script>` that is not either JSON-LD or a
first-party module, and scans the first-party modules for network and storage
APIs.
